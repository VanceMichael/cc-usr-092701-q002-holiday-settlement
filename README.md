# 节日商圈结算协同

面向节日活动（品牌快闪、夜游项目、餐饮节等）结束后的结算协同领域服务。销售额、
商圈客流、银联消费数据分批到达，各渠道券码与补贴额度独立；服务把企业、活动、
券批次、核销、退款和支付对账记录统一接入，按活动规则冻结可用额度，在结算窗口
生成可解释、可追溯的分账结果。

数据均为演示用虚构内容。

## 要解决的问题

- **数据分批、乱序**：核销可能早于银联支付到达，退款可能早于核销到达；服务先
  挂起（await_payment / await_order / await_quota），依赖齐备后自动消化，重启不丢单。
- **渠道重传**：同一记录号重复投递且内容一致 → 幂等忽略；**金额相同但订单内容
  不同**（换单）→ 内容指纹不同，进隔离区并挂争议，原记录不被覆盖。
- **一笔消费不能两次补贴**：以支付单号为消费去重键，跨活动全局唯一；同一券码
  也只能核销一次。第二次补贴直接拒绝并指明首享活动。
- **跨店退款责任**：退款发起方与补贴收取方不一致时挂起争议单，补贴款项不动，
  只有**审计角色**可解锁并指定承担企业，解锁结果单独成事件可追溯。
- **封账不可变**：结算窗口封账生成一次性快照（含事件链尾哈希与自身指纹），
  永不覆盖；商户补报的历史记录只能成为"后期调整"，快照数字不变。
- **额度勾稽**：预算池 / 活动 / 券批次 / 订单四层金额始终相互吻合；封账后退款
  不回冲快照已结算，而是记为对承担企业的应返还。
- **可解释、可追溯**：每笔分账给出规则文本与算式（如 `800.00 × 0.2 = 160.00`，
  含单笔封顶），管理者可从商户汇总行下钻到原始核销、银联支付、退款及每次调整。

## 角色分工（RBAC）

| 角色 | 能做 | 不能做 |
|---|---|---|
| 财务 `finance` | 封账、分账、确认封账后补报 | 维护活动规则/预算/批次、解锁争议 |
| 活动主办方 `organizer` | 登记年度预算、活动规则、券批次 | 金额动作、解锁争议 |
| 审计 `auditor` | 解锁争议单（执行/驳回退款、受理/拒绝隔离记录） | — |

## 架构

事件源（event sourcing）+ 仅追加日志，状态全部由事件重放得到：

```
命令（接入/封账/解锁）
        │  先校验角色与业务规则
        ▼
EventStore（events.log.jsonl，哈希链 prev_hash → digest，fsync 落盘）
        │  重放
        ▼
SettlementService 内存态（预算池/活动/批次/订单/争议/挂起/隔离/调整）
        │  封账
        ▼
snapshots/<id>.json（一次性写入、不可覆盖，绑定事件链尾哈希）
```

- `src/holiday_settlement/model.py`：值对象与纯函数；金额统一 `Decimal` 两位
  小数，订单内容经规范化 JSON 计算 SHA-256 **内容指纹**。
- `src/holiday_settlement/store.py`：仅追加事件日志、哈希链校验、不可变快照。
- `src/holiday_settlement/service.py`：结算协同领域服务（额度生命周期、去重、
  隔离、争议、封账、后期调整、勾稽与溯源）。
- `src/holiday_settlement/cli.py`：端到端演示与复查命令。

### 订单额度生命周期

```
核销受理 ──冻结(frozen)──┬─ 窗口内退款 ─► 释放冻结（recovered）
                        ├─ 封账 ───────► 已结算(settled)，写入快照
                        │                 ├─ 封账后退款 ─► 应返还(recovered)，快照不动
                        │                 └─ 争议挂起单 ─► 解锁后走补报通道
                        └─ 封账后补报 ─► late_pending ─财务确认► late_settled（后期调整）
```

共享年度预算池在池层面聚合各活动的冻结/已结算/后期金额；活动也可使用独立额度。

## 命令行

```bash
# 端到端演示：品牌快闪 / 夜游 / 餐饮节，含乱序、重传、双补贴拦截、跨店争议、
# 封账、补报、封账后退款、勾稽全流程
python3 -m src.holiday_settlement.cli demo --dir .settlement-demo --fresh

# 服务重启：再次运行即从事件日志完整重放（不产生重复决定）
python3 -m src.holiday_settlement.cli demo --dir .settlement-demo

# 额度勾稽 + 事件哈希链校验
python3 -m src.holiday_settlement.cli verify .settlement-demo

# 从一笔商户汇总追到原始核销、银联支付、退款与每次调整
python3 -m src.holiday_settlement.cli trace .settlement-demo FOOD M-火锅

# 领域资料摘要（原有功能）
python3 -m src.holiday_settlement.context fixtures/context.json
```
